Architecture Overview

This section of the documentation describes how Refitter works internally: how an OpenAPI specification becomes Refit interfaces and contracts, how that differs between the three distribution forms (CLI tool, MSBuild task and C# Source Generator), and how the project is tested to avoid regressions.

Two details in this picture are easy to miss:

  • Refitter.MSBuild does not reference Refitter.Core. It contains a small MSBuild task and the complete build output of the CLI for each supported runtime. At build time it starts the CLI as a dotnet child process. See MSBuild Task Internals.
  • Refitter.SourceGenerator does not reference the Refitter.Core package either. Analyzers cannot reliably load arbitrary package dependencies, so the generator project compiles the Refitter.Core source files (<Compile Include="../Refitter.Core/..." />) into its own assembly and ships its third-party dependencies inside the analyzer folder. See Source Generator Internals.

One shared entry point

All three distribution forms end up in the same method: RefitterRunner.RunAsync. What differs is how settings arrive, whether files are written, and whether the OpenAPI specification is validated.

RefitterRunner.RunAsync takes a RefitGeneratorSettings object and two optional collaborators:

  • an IFileWriter, which the CLI provides (CliFileWriter) and the source generator leaves out, so nothing is written to disk from inside the compiler;
  • an IValidator, which the CLI provides unless --skip-validation is set, and the source generator leaves out.

It always returns a RunResult and never throws. Exceptions are captured as error diagnostics, and ExitCode is set to the exception's HResult.

Library responsibilities

Refitter does not parse OpenAPI documents or generate DTOs on its own. It combines several libraries:

Library Used for
NSwag (NSwag.Core.Yaml, NSwag.CodeGeneration.CSharp) The OpenApiDocument model, $ref resolution, and generation of the contract (DTO) types. Refitter subclasses CSharpClientGenerator but turns off NSwag's own client generation
NJsonSchema JSON schema model, type resolution and the Liquid templates for classes, records and enums
Microsoft.OpenApi via OasReader OpenAPI validation, statistics, and reading specifications whose external references must be merged into one document
YamlDotNet (via NSwag.Core.Yaml) Converting YAML specifications to JSON before NSwag parses them
Roslyn (Microsoft.CodeAnalysis.CSharp) Rewriting generated contracts and building the JsonSerializerContext, and in the source generator, running the nested Refit and System.Text.Json generators
Spectre.Console CLI argument parsing and rich console output

The Refit interfaces themselves are not produced by NSwag. Refitter writes them with its own InterfaceGenerator, using NSwag's operation and parameter models to resolve types. See Code Generation Pipeline.
